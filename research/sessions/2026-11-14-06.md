# Sessão 25 - 2026-11-14 (`S12`: Assinatura Android Persistente entre Builds Locais, CI e OTA)

## Objetivo

Corrigir a incompatibilidade de assinatura entre builds Android consecutivos gerados pelo GitHub Actions (`43626533694` vs `43632103622`), que impedia instalar um APK novo por cima da versão já instalada e quebraria atualizações automáticas in-app (`Updater` / `ApkFileProvider`).

## Causa Raiz

- O arquivo `.gitignore` continha `*.keystore`, impedindo o versionamento de `android/app/heroes_lore_3.keystore`.
- Em cada execução limpa no GitHub Actions, `tools/prepare_platform_assets.py android` executava `ensure_android_keystore()` -> `keytool -genkeypair`, gerando um novo par RSA-2048 efêmero com certificado distinto a cada build.

## Correções Aplicadas

1. **Keystore persistente no repositório + override opcional por Secret (`*.keystore` + `!android/app/heroes_lore_3.keystore`, `.gitattributes`, `.github/workflows/build.yml`, `android/app/build.gradle`)**:
   - Liberado `android/app/heroes_lore_3.keystore` (certificado RSA-2048 SHA-256 `61ca6931c36cc8f1139b9922a07fd5e1e5479c935ed7c12728296b5f1dac4905`) no `.gitignore` e marcado `*.keystore binary` / `*.jks binary` em `.gitattributes` (evitando corrupção CRLF->LF de PKCS#12 pelo `* text=auto eol=lf` no checkout Linux do CI).
   - `android/app/build.gradle` passou a configurar `signingConfig signingConfigs.release` de forma obrigatória no buildType `release`.
   - `.github/workflows/build.yml` passa a aceitar override opcional via secret `HL3_KEYSTORE_BASE64` (ou usar o keystore versionado por padrão).
2. **Guardas de pipeline & testes (`tools/prepare_platform_assets.py`, `tools/verify_android_package.py`, `tests/test_multiplatform_ci.py`)**:
   - Adicionado `--require-existing-keystore` (e suporte a `HL3_KEYSTORE_PATH`) em `tools/prepare_platform_assets.py` para o CI falhar caso o keystore não exista, em vez de criar chave aleatória.
   - Adicionados `--require-signed` e `--expected-cert-sha256` em `tools/verify_android_package.py` usando `apksigner verify --print-certs` (com regex compatível tanto com `Signer #1 certificate SHA-256 digest:` quanto `V2 Signer: certificate SHA-256 digest:`), aplicados no CI para ambos os APKs (`arm64` e `universal`).
   - Adicionadas asserções em `tests/test_multiplatform_ci.py` garantindo keystore rastreada no git, `--require-existing-keystore`, `--require-signed` e `EXPECTED_HL3_CERT_SHA256`.

## Validações Executadas

- `python tools/prepare_platform_assets.py android --require-existing-keystore`: `OK`.
- `python tools/verify_android_package.py dist/heroes_lore_3_android_arm64.apk --abis arm64-v8a --require-signed --expected-cert-sha256 61ca6931c36cc8f1139b9922a07fd5e1e5479c935ed7c12728296b5f1dac4905`: `PASS`.
- `python tools/verify_android_package.py dist/heroes_lore_3_android_universal.apk --abis arm64-v8a armeabi-v7a x86_64 --require-signed --expected-cert-sha256 61ca6931c36cc8f1139b9922a07fd5e1e5479c935ed7c12728296b5f1dac4905`: `PASS`.
- `git check-ignore android/app/heroes_lore_3.keystore`: saída `1` (rastreado pelo Git).
- `python -m unittest discover -s tests -p "test_*.py"`, `python tools/project_status.py check`, `python tools/bump_version.py --check`, `python tools/verify_workspace.py`.
